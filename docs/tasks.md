# ToDo(タスク・ルール)

やることのメモ(タスクとプロジェクト)と、Claude Code に守らせたい共通ルールを持つ層。
**メモを溜めて後から引く**という点で [notes](api-reference.md#chiezo_memory短期記憶の-rest) と
同じことなので、別の置き場を持たずに notes の上に載せている。

- **プロジェクトとタスク**は置き場と REST(`/v1/todo/...`)だけを持つ。操作するのは
  LAN の中のタスクと予定のアプリで、Chiezo の管理画面には出さない
- **ルール**は管理画面の記憶の面のいちばん下の節(**`/admin/memory#rules`**)で書く

実装は、画面が `app/views/todo.py`、ドメイン層と REST が `app/tasks.py`。

## 専用のテーブルを持たない

タスクもルールも `chiezo_memory` の文書 1 件で、**種別・状態・所属はタグで表す**。
おかげでスキーマの変更が 1 つも要らず、**`task` タグを付けたメモが
そのままタスクとして並ぶ**。基準を `todo` にしないのは、あれが「あとでやる」くらいの
意味で普通のメモにも付くため(基準にすると、メモがタスクに化ける)。

| 概念 | 表現 |
|---|---|
| タスク | tag `task` の文書 |
| 状態 未着手 | 状態のタグが無い(既定) |
| 状態 着手中 / 完了 | tag `着手中` / `完了` |
| 「直すのが大変そう」の印 | tag `難所`(状態とは別軸) |
| タスクの所属 | プロジェクト名のタグ(リポジトリ名をそのまま使う既存の慣習に乗る) |
| プロジェクト | 設定の置き場(`chiezo_settings`)の**1 件**に、全部を JSON でまとめて持つ |
| プロジェクトのアーカイブ | その JSON の `archived` |
| ルール | tag `rule` の文書。本文が Markdown |
| ルールの無効 | tag `無効` |

## プロジェクトとタスクは外のアプリから操作する(`/v1/todo/...`)

タスクと予定を扱うアプリが、Chiezo の ToDo を保存先にできるように、タスクとプロジェクトを読み書きする
REST を持つ(`docs/api-reference.md`「ToDo の REST」)。アプリが持ちたい項目(期日・繰り返しなど)は
`data` として預かるだけで中身は見ない(`docs.extra` の `data`)。ほかの `/v1` と同じく LAN の中だけで使う。

**管理画面からはプロジェクトとタスクの画面を外した。** 操作をそのアプリに一本化したためで、
画面にも同じ操作を残すと、同じタスクを 2 か所で直すことになり、どちらが正なのかが読めなくなる。
あわせて、画面にあった書き出しと取り込み(JSON での控え)、完了の一覧、Claude Code へ渡すリンクも外した。
置き場はそのままなので、MCP の `recall` やブラウズ画面(`/search/chiezo_memory/`)からは今までどおり読める。

## 外に出す面を持たない

**Chiezo は安全なネットワークの中からしか触らせない。** ポートを外へ開かないこと。

以前は、やること層だけを Google のログイン付きで外へ公開する別プロセス
(`chiezo-tasks` / 7015)を立てられるようにしていた。本体(7010)を公開すると
次のものが一緒に外へ出てしまうので、**面をプロセスごと分ける**という考え方だった:

| 口 | 公開した場合 |
|---|---|
| `POST /v1/ai/complete` | サーバー側の鍵で AI を叩ける |
| `POST /v1/media/image\|audio\|video\|speech` | 生成が走る。課金に直結 |
| `/admin` | 数時間かかる取り込みを起動できる |
| `DELETE /v1/chiezo_memory/{doc_id}` | メモを消せる |

この分け方はやめて、**外に出す面ごと畳んだ**。理由は 2 つ:

- **守る面が 1 つでも外にあると、守りを持ち続けることになる。** 認証・CSRF・
  レート制限・リダイレクト URI の許可リスト・セッションの置き場は、どれも
  「外に出しているから要るもの」で、出さないなら丸ごと要らない
- **画面の作りが 2 系統あった。** 管理画面はサーバーで組んだ HTML、やること層は
  ビルドの要る SPA(Vue + PWA)。同じサーバーの中で操作の見た目も配り方も違い、
  直すたびにどちらの流儀かを思い出す必要があった

LAN の中のアプリが `/v1/todo/...` で読み書きするのは、これとは別の話 ——
畳んだのは外に出す面で、LAN の中のアプリから読めないようにしたわけではない。

## ルールの画面(`/admin/memory#rules`)

**記憶の面のいちばん下に置く。** ルールは短期記憶のメモにタグで載っているだけなので、
面を分けると帯に同じ層の入口が 2 つ並ぶ。書き込みの口は `/admin/todo/rules/...`
(`GET /admin/todo` そのものは無い)。

- **JS はインラインの `confirm` まで**(管理画面の流儀)。開閉は `<details>`、
  並び替えはドラッグではなく ↑↓ のフォーム。確認を出すのは取り消せない操作にだけ
- **一覧の行を開くと、そこで編集できる。** 読むだけの行と編集の画面を分けない
- **書いたら押した場所へ戻る**(303 + `#アンカー`)。断られた理由は `?error=` で
  帯に出す —— ドメイン層は `HTTPException` を投げるので、素通しすると画面の
  代わりに JSON が出る
- **有効なルールだけを 1 本の Markdown に連結して出す**(「まとめて表示」)。
  これを規約リポジトリの CLAUDE.md に丸ごと貼り替え、Claude Code のセッションに
  含めて読ませる。規約リポジトリの URL は貼り替える先の控えとして画面で持つ

## ルールの取り込み

「まとめて表示」で出る 1 本の Markdown を貼り付ければ戻せる(`## 見出し` で区切る)。
入れ替えも追加も、先に「下見」で何が入るかを出す。**無効にしてあるルールは連結に載らない**ので、
移したいなら連結する前に一時的に有効へ戻すこと。
