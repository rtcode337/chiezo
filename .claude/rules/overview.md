# Chiezo が持っているもの(全体像)

Chiezo が貸し出すもの(知識・鍵と話せる AI・計算資源・時計と置き場)の全体像。機能をまたぐ設計を考えるときに読む。各部の詳しい記述は、ルートの CLAUDE.md の索引にある各ルールファイルにある。

## 持っているもの

### 知識(溜めて引く)

- **ためる** — `ingest/` がソースごとに独立した SQLite ファイル(`data/corpus/<source>.db`)を作る。
  取得元は公開ダンプ(Wikipedia / OpenStreetMap / GeoNames / Overture / 内閣府の祝日 `holidays_jp`)と、
  キーの要る API(J-Quants の上場銘柄一覧 `jquants_master` と決算発表予定日 `jquants_earnings`。
  後者は件数が時期で増減するので `allows_shrink` を名乗り、前の世代より大きく減っても焼く。後者は
  **全部が見えるのは有料プランのキーだけ** —— 参照範囲が公表日で決まり、無料プランでは先の予定がほぼ
  見えない。取り込みの最初に公表日=今日で 1 回問い合わせてプランを判別し(参照範囲外の 400 なら無料)、
  **無料でも止めずに見える分だけ焼き、どのプランで取ったかを 1 件の文書に残す**(タグ `取得状況`・
  脇書きの `plan` / `coverage`)。読む側のアプリはそれを見て「一部しか載っていない」と添えて AI に渡す。
  無料プランは 1 分に 5 回ほどで 429 になるので、問い合わせの間隔を 13 秒に広げる。**それでも 429 が
  返ったら止めずに待って問い合わせ直す**(倍々に 5 回まで。同じキーを別のアプリで同時に使うと当たる)。**個人の私的利用に限る** ——
  本人以外が見られる環境では取り込まない、解約したら消す。`ingest/sources/jquants.py` の冒頭)に限らず、
  **キーが要るソースは `credential_label` を名乗る**。API キーではない形の認証情報
  (接続先とパスワードを `<URL> <パスワード>` の 1 つの欄に書くもの)は、
  入力欄の見本を `credential_placeholder` で名乗る(カタログの `credential.placeholder`)。trigger のカタログに `credential` が載る。
  **外部 API のキーは管理画面の「API キー」の面(`/admin/keys`)に名前で持つ**(`settings.db` の
  `api_keys`)。**使う側は名前で引く** —— ソースは `credential_group` でキーの名前を名乗り
  (J-Quants の 2 つは `jquants`。名乗らなければソース名)、これから足す収集の道具も同じ名前で引く。
  ソースごとに持つと同じキーを何度も入れ、入れ替えたときに片方だけ古いまま残る。ソースが名乗らない
  キーも名前を付けて置いておける(道具が後から引く)。
  登録したキーは初期化・再構築のたびに `POST /run/{source}` の本文で
  trigger へ渡す(`views.admin.trigger_run`)。**trigger は環境変数に書かず、その 1 本の
  アダプタにだけ入れる**(`main.run(credential=)`)。状態にもログにも残さない。このリポジトリに
  入れられないものは**別コンテナのプラグイン**(`CHIEZO_PLUGIN_SOURCES`)から足せる。
  更新はブルーグリーン
- **取り出す** — `app/` が **MCP**(`/mcp`)と **REST**(`/v1/...`)の 2 経路で出す。
  Claude Code 向けには「いつ Chiezo を使うか」を書いた CLAUDE.md ブロックも生成する
- **覚える** — `app/notes.py` が **書き込めるソース** `chiezo_memory` を持つ(外のアプリ用の
  名前付きの置き場 `/v1/stores` も同じ形)。
  **書き手は AI でもよい**(MCP の `remember`)。「覚えておいて」と言われたことを溜め、
  `recall` で新しい順に引く。CLAUDE.md や記憶ファイルと違い**常駐するのはツール定義だけ**
  なので、件数が増えてもコンテキストを食わない
- **集める / 育てる** — `app/collect.py` が、**まとまったダンプの無いもの**を AI に
  集めさせて長期記憶へ溜めていく(直近のニュース、入れ替わりの速い店の情報、人物の関係)。
  **同じ機械で「既にある内容を育てる」こともできる** —— 依頼文に今ある内容を
  差し込めば(`{current}` / `{recent}`)、直すものと足すものだけを返させる回になる
  (返さなかったものは残る)。**回ごとに決まる**ので、同じ収集の中で足すだけの回と
  直す回を並べられる。
  **どちらにも機械の道具が付く** —— 手元の長期記憶から引く `extract`(`app/extract.py`)と、
  外の RSS / Atom から引く `feed`(`app/feeds.py`)。**道具が取ってきたものは参考**で、
  何を溜めるかは AI が決める(自分でも web を検索し、渡されたぶんも含めて採否を判断する)。
  **育てる側は区画で回る**(`app/partition.py`)—— 対象としている空間を密度で割って
  順に見るので、まだ 1 件も集めていない範囲にも「足すべきものが無いか」を聞ける。
  **巡回は 1 本とは限らない**(`Sweep`)。ざっと全体を拾うものと、少数をじっくり調べるものを
  別の時計で回す。**「ここが間違っている」は割り込みで頼める**(`Focus`。定時の巡回の
  進み具合には触らない)。**割り込みも巡回として定義しておける** —— 時計を持たない
  1 本(`on_demand`)で、頼む相手を定時のものと別に決めておくためのもの。
  **時刻を外のアプリが決める巡回もある**(`by_caller`。時計では走らず、名指しの
  `…/run` はふつうの回として走る)。
  **焼かずに名前付きの置き場へ書く収集もある**(`store`。取り込みを通さず chiezo-app の
  中で走り、巡回はすべて `by_caller`。`collect.md`「置き場へ書く収集」)。
  **その回だけの依頼文も差し込める**(保存はしない)。**1 回ごとの変更履歴が残る**(`app/collect_log.py`)。
  **焼くのは ingest**(`ingest/sources/collect.py`。取り込み側のプラグイン契約)——
  **長期記憶へ書けるのは ingest だけ**という線をこの層でも崩さない。
  **素材が「前世代 + いま集めたぶん」になる**ので、ブルーグリーン(全件の作り直し)に
  乗せたまま追記として積み上がる(世代は今と 1 つ前だけ)。**集めるのは取り込みの中**
  (ingest が素材を取りに来た瞬間に AI を呼ぶ)なので、**途中の置き場を持たない**。
  溜め先は収集ごとに別のソースで notes には混ぜない —— 短期記憶が収集物で
  埋まると `recall` も画面も使えなくなる。**時計は Chiezo が持つ**ので間隔は画面から変えられる

ためた知識(公開ダンプ)と集めた知識はどちらも `corpus/` の読み取り専用
ソースで、**引く口はまったく同じ**。違うのは素材が外にあるか手元にあるかだけ。
**画面では「長期記憶」「短期記憶」と呼ぶ**(`/admin/memory` の 2 節。
短期記憶の表には、覚えたことの置き場(`chiezo_memory`)と設定の置き場
(`chiezo_settings`)が並ぶ —— どちらも書き込める側なので分けない)。

### 鍵と、話せる AI

**呼ぶ側に認証情報を持たせない**のがこの面の値打ち。鍵は管理画面から入れて
`app/settings_store.py` が預かり、相手ごとの接続は `app/providers.py` が決め打ちで持つ。

- **取り次ぐ**(`/v1/ai/backends`・`/v1/ai/complete`)—— **知識ベースを介さない素の口**。
  自分のプロンプトと材料を持っているアプリ向けで、借りたいのは「話せる相手と鍵」だけ、
  という使い方(別のアプリの売買提案やサマリー生成)。`/v1/chat` は必ず抽出を
  混ぜるので、この用途には使えない
- **使ってみせる**(`/v1/ask`・`/ai/chat`。任意・既定では無効)—— **Chiezo を上手に引ける
  AI を Chiezo 自身が用意する**もの。どう引けば当たるかをいちばん知っているここが道具立てと
  プロンプトを持つ、という考え方(`scripts/gen_claude_config.sh` が Claude Code 用の設定を
  配るのと同じ)。`app/answer.py` が受け、推論は同居させず OpenAI 互換 API を叩くだけ。
  `?mode=agent` では `app/agent.py` が MCP と同じ道具を LLM 自身に引かせる
  (GPU + 8B 級が前提なので**既定は 1 回検索する `rag`**)。会話として続けるのが
  `/v1/chat`(履歴はクライアントが持つ)
- **CLI ブリッジ**(`bridge/`)—— Claude Code / Codex / Antigravity の CLI を OpenAI 互換の口に
  見せる。サブスクの枠で動く相手を、API キー方式と同じ形で貸し出すため
- **話し続ける**(`/v1/talk`。`app/talk.py` + 会話ブリッジ `bridge/talk_bridge.py`)——
  短期記憶に置いたキャラ設定のまま、相手(いまは codex)と会話を続ける。相手を起動したまま
  会話ごとにスレッドを持つので、1 往復ごとに CLI を起こさず、履歴も送り直さない。
  **CLI ブリッジとは別のコンテナ・別のサインインにする** —— CLI ブリッジは codex を
  1 本ずつしか動かさない(`cli_slot`)ので、同居させると会話が枠を握り続けて他の依頼が
  通らない。サインインを共有すると refresh token の回転がぶつかって失効する。
  **会話の id はブリッジのスレッドの id に相手の名前を付けただけ**(chiezo-app は状態を
  持たない)。ブリッジが再起動したら 404 を返し、呼ぶ側に始め直させる(黙って作り直すと
  文脈が切れたことに気づけない)。**web 検索は既定で閉じる** —— codex は既定で開いていて、
  道具の一覧に出ないまま外を調べて答えた(実測: 知識ベースを 1 度も引かずに公式サイトを
  出典に挙げた)。キャラの人柄は持たない(呼ぶ側が短期記憶に置く)。こちらが足すのは
  道具の引き方の決まりごと(`TALK_RULES`)だけ
- **使用量と失敗の控え**(`app/usage.py` / `app/ai_log.py`)—— 貸し出す以上、
  **枠の残りと、なぜ失敗したかが後から読める**必要がある(無人の呼び出しは、
  その場に居合わせない人が原因を追うことになる)

### 計算資源と外への回線

- **絵・音・動画・声・文章**(`app/media.py`)—— 自前の GPU(ComfyUI)でも外部サービスでも、
  同じ口から頼める。**鍵は「話す相手」のものを流用する**(同じ鍵を 2 か所に入れさせない)。
  **文章だけは「話せる AI」に書かせる**が、job として残す仕組みは同じ ——
  見比べも採用の印も kind を問わずに動くので、分けると口も画面も二重になる
- **文字起こし**(`transcribe`)—— 向きが逆なだけで置き場も掃除も同じ仕事なので、
  同じ層に置いてある
- **web 検索**(`app/websearch.py`。既定では無効)—— 溜めた知識の外側を補う。
  **知識ベース本体は外を叩かない**という線は崩さない

### 時計と置き場

- **定期実行** —— 「集める」の時計(`main._run_collections`)と、長期記憶の定期再構築の時計
  (`main._run_rebuilds` / `app/rebuilds.py`。ダンプのソースを何日おき・何時〈日本時間〉に取り直すかを
  ソースごとに `machine_store` に持つ。次の回は「前に起こした日 + 間隔」の決めた時刻で、**時刻ではなく
  日付で数える**〈空き待ちで遅れても次は決めた時刻に戻る〉。ダンプの枠が空いているときだけ 1 周に
  1 本起こし、起こせたときにだけ予定を進める)。ホストの cron に出さないのは、
  間隔を画面から変えられるようにするため
- **生成物の置き場**(`/media/...`)と、**何案か作って人に選ばせる場**(`media_picks`)——
  音は AI 自身が聴けないので、聴き比べる手段がここにしかない
- **ToDo**(`app/tasks.py` / 画面は `app/views/todo.py`)—— タスク・プロジェクト・ルールを
  `chiezo_memory` の上にタグで載せたもの。専用のテーブルも列も持たない。
  プロジェクトとタスクは LAN の中のアプリが `/v1/todo/...` で読み書きし(アプリの項目は `data` として
  中身を見ずに預かる)、操作はそのアプリに一本化している。**管理画面に出すのはルールだけ**

現在の収録ソースは日本語 Wikipedia = `jawiki`、OpenStreetMap 日本抽出 = `osm_japan`、
GeoNames 全世界地名辞典 = `geonames`(いずれも 348 言語版・195 か国から選んで増やせる)。
