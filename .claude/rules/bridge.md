# CLI ブリッジ(bridge/)

Claude Code / Codex / Antigravity の CLI を OpenAI 互換の口に見せる別イメージと、会話ブリッジ。

## CLI の内蔵ツールで絵を作る

- **画像は CLI の内蔵ツールでも作れる**(`/v1/images/generations`。**持っているのは
  Codex と Antigravity だけ**で、claude は持たない。どちらも「エージェントにファイルを
  書かせる」形なので、ブリッジの段取りは共通で違うのは起動コマンドだけ)。**課金は ChatGPT の
  サブスク枠**で、API キーの `openai` とは別勘定(同じ gpt-image-2 でも出どころが違う)。
  **`model` の意味がこの 2 つだけ違う**: 他の相手は絵のモデルを選ぶが、ここで選ぶのは
  **描かせるエージェント**のモデル(`codex -m` / `agy --model`)。絵のモデルは内蔵ツールが
  決めるので指定できず、`models` を空にしてあるのはそのため。記録には描かせた相手を添える。
  **実際に描いたモデルは絵そのものから読む**(`image_model_of`)—— 返ってくる PNG の
  `caBX` チャンクに Content Credentials(C2PA)が入っていて、その CBOR の
  `softwareAgent` に名前と版がある(実測で name=gpt-image / version=2.0)。
  CBOR は丸ごと解かずその並びだけを読み、読めなければ控えの名前に落とす
  (**モデル名が分からないだけで失敗ではない**ので、絵は返す)。
  会話の口は `-s read-only`、**画像の口は `-s workspace-write`(作業ディレクトリだけ書ける)**で、
  **どちらもシェルの道具を外す**(`CODEX_NO_SHELL` = `--disable shell_tool --disable unified_exec`。
  read-only は「読ませない」ではないので、シェルが残るとコンテナ内のファイルを読める)。
  **元の絵は添付(`codex exec -i`)で渡す** —— ファイルの口(`referenced_image_paths`)は
  codex 自前のサンドボックス(bubblewrap)越しに読むので、非特権のユーザー名前空間を作れない
  ホストでは `bwrap: No permissions to create a new namespace` で落ちる(書き出しは内蔵ツールが
  直に行うので通り、**編集だけが「画像を保存しませんでした」に見えていた**)。以前はそれを
  避けるために `danger-full-access` で走らせていたが、添付は CLI 自身が起動時に読むので
  サンドボックスを緩めなくて済む。**添付のほうを使えと名指しする**(`SOURCE_HINT`)。
  **シェルが無いので、内蔵ツールは共有の保存先に置いたまま**になる(写そうとして失敗を
  重ねるので、写さなくてよいと言い添える `SAVE_NOTE`)—— 拾うのは下の共有の保存先の道。
  実測(codex 0.149.0): `-i` + workspace-write + シェルなしで、編集した絵が共有の保存先に出た。
  拾うのは**その実行で増えた画像だけ**(保存先は使い回されるので、前回のぶんを混ぜない)。
  **作業ディレクトリを先に見て、共有の保存先(`$CODEX_HOME/generated_images`)は
  走らせる前にあったものを除く。さらに直列化する**(`cli_slot`)—— 共有の保存先を
  時刻だけで選ぶと、同時に走った別の実行の絵を返す(4 件同時に頼んで 4 件とも同じ絵が返った)。
  相手はエージェントなので、**保存先と枚数を言い切る**(曖昧だと説明だけ返してファイルを書かない)。
  **Antigravity は頼んだ場所へ直接書く**ので共有の保存先を見る必要は無いが、
  **音と動画の道具は持っていない**(バイナリに imagegen のハンドラはあるが、
  動画は protobuf の型だけで実装が無く、実際に頼んでも何も出ない)

## bridge/

- **`bridge/` — CLI ブリッジ(別イメージ `ghcr.io/<owner>/chiezo-bridge`)。**
  Claude Code CLI / Codex CLI / Antigravity CLI を OpenAI 互換の口に見せる。
  **イメージは 1 つで、`CHIEZO_BRIDGE_CLI` で役割を決める** —— イメージは 1 回 pull すれば
  ディスクは 1 つぶんで、コンテナを何個立てても増えるのは書き込み層(数 KB)だけなので、
  分けるより 1 枚が得。
  **node は最終イメージに入れない**(claude は自己完結バイナリ、codex も vendor の
  実体を直接叩ける)。**Gemini CLI は個人向けの提供が 2026-06-18 に終了したので外した** ——
  あれだけが JS バンドルで node を要求していた(後継は Antigravity CLI)。**amd64 のみ**ビルドする
  —— codex の vendor パスに x86_64 が直書きしてあるので、arm64 を作るならそこも変える。
  **MCP は任意**(`CHIEZO_BRIDGE_MCP_URL` を空にすると繋がない)。Chiezo 専用の部品ではなく、
  他のアプリからも使えるサービスとして立てられる。
  **本体には入れない** —— `chiezo-app` が数百 MB で動く前提を崩さないため(推論を同居させないのと
  同じ理由)。既定では立たず、`docker-compose.llm.yml` のコメントを外した人だけが pull する。
  - **プロンプトの渡し方は CLI ごとに違う。** claude / codex は標準入力から読むが、
    **agy(Antigravity)は `-p` の引数でしか受け取らない** —— 標準入力は読まず
    (`-p -` は "-" をプロンプトそのものとして扱う)、プロンプトを取るファイル用のフラグも無い。
    そのため Linux の単一引数の上限(MAX_ARG_STRLEN = 128KiB)に当たる。
    **超えるぶんはファイルに書いて読ませる**(`--add-dir` で作業対象に入れる)。
    短いプロンプトは今までどおり引数で渡す。
    **`--dangerously-skip-permissions` は長さに関わらず付ける** —— 道具を使うかは
    長さではなくモデルが決める(MCP を繋いであり、web で調べる頼み方もする)。print モードには
    確認の対話が無く、付けずにいると道具が要った瞬間に `invalid arguments: - missing
    properties 'toolSummary', 'toolAction'` で落ちる。かつて「短いプロンプトは道具も権限も
    要らない」として付けていなかったが、agy の版を 1.1.13 → 1.1.27 に上げても同じ落ち方をした
    (絵を描く口は最初から付けていて、そちらは通っていた)。
    断って 413 を返していた頃は、外のアプリの売買提案(候補ショートリスト込みで 120KiB 超)が
    毎回失敗していた。**書き出したファイルは答えを返す前に必ず消す**(中身はプロンプトそのもの)
  - **絵を描かせている間の出力は、読みながらログへ流す**(`_pump`)。
    `communicate()` は相手が終わるまで 1 バイトも渡さないので、**上限で打ち切って
    kill すると、そこまでの出力ごと消える** —— 実測で、20 分待って 504 になった回の
    ログは「開始」と「504」の 2 行だけだった(描いていたのか、確認を待っていたのか、
    そもそも動いていなかったのかを切り分けられない)。**打ち切るときも言い分を残す**
    (504 の `said`)。**`readline()` は使わない** —— base64 を吐く相手がいるので
    限度超えで落ちて取りこぼす。標準入力へ渡すのは読み出しと同時に走らせる
    (先に書き切ろうとすると、相手が出力を吐き続けたときにパイプが詰まる)
  - **CLI の出力は構造化して受け取る**(`_result_of`)。claude と antigravity は
    `--output-format json`、codex は `--json`(JSONL。本文は今までどおり `-o` の
    ファイルから取り、使ったぶんだけ標準出力から読む)。素のテキストは最終的な答えしか
    運ばないので、**トークン数も「エラーとして終わったか」も捨てていた** ——
    claude は `subtype` が "success" のまま `is_error` が立つ回があり(実測: 未サインイン)、
    終了コードしか見ていなかった頃はその文面が答えとして保存されていた。
    **読めなければ本文だけ返す** —— 出力の形は CLI の版で変わりうるので、読めなくなった
    日に全部の呼び出しが落ちるのでは割に合わない(落とすのはトークン数だけにする)。
    **キャッシュから読んだぶんは入力の内訳**として返す(`prompt_tokens_details.cached_tokens`)。
    外に足すと、キャッシュが効いているほど使用量が大きく見える ——
    **Anthropic だけ `input_tokens` がキャッシュを含まない**数え方なので、そこだけ足して揃える
  - **道具は CLI 自身に引かせる**。Chiezo の MCP(`/mcp`)を CLI に繋ぐので、検索して答える
    段取りをブリッジ側で組まない。Chiezo から見ると「1 回聞いたら答えが返る」ので
    `rag` / `agent` の区別は関係なくなる
  - **組み込みの道具は渡さない**。知識ベースに答えるのにシェルもファイル操作も要らず、
    使えると危ない(コンテナには自分の認証情報がある)。**claude は許す側の一覧で絞る**
    (`--tools ToolSearch` + `--permission-mode dontAsk` + `--allowed-tools mcp__chiezo`。
    web を頼まれた回だけ `WebSearch` / `WebFetch` を足す)—— 以前の「`bypassPermissions` +
    塞ぐ一覧(`--disallowed-tools`)」は一覧に無い Grep・Glob を通していた。`--tools ""` は
    ToolSearch ごと消えて MCP が引けなくなるので使えない(実測: `--tools ToolSearch` なら
    起動時の道具は ToolSearch と mcp__chiezo__* だけになり、MCP は引けた)。
    **codex はシェルの道具を外す**(`CODEX_NO_SHELL`)。**agy は許す道具を名指しする口が無い**
    ので `--dangerously-skip-permissions` のまま —— 守りはマウント(ホームだけ)と
    ネットワーク(compose の `chiezo-ai`。chiezo-app と外には届くが chiezo-trigger には
    届かない)で取る
  - **認証情報はイメージに焼かない**。管理画面から登録したものを、chiezo-app が書き出した
    その相手の分だけの写し(`/credential/credential`)から要求のたびに読む(無ければ以前の
    置き方の設定 DB → 環境変数へ落ちる)。ファイルが要る Codex だけ `apply_credential()` が
    `$CODEX_HOME/auth.json` へ置く
  - **登録された auth.json は「種」で、既にあるものへ書き戻さない**(`_seed_auth_file`)。
    Codex は access token が切れると refresh token で更新をかけ、相手は更新のたびに
    refresh token を回転させて古いほうを無効にする。回転後のファイルを登録時の内容へ戻すと、
    次の更新が使用済みの refresh token で走り、盗用とみなされて一連の権限ごと失効する
    (`Your refresh token has already been used to generate a new access token.`)。
    **サインインし直すまで戻らない**うえ、期限切れとは無関係のタイミングで起きるので原因を
    追いにくい(実際に踏んだ)。上書きしてよいのは、ファイルがまだ無いときと、管理画面で
    登録し直したときだけ。**中身の比較では見分けられない**(回転で中身は変わる)ので、
    最後に流し込んだ値の指紋(sha256)をホームに残して突き合わせる ——
    残すのはハッシュだけで、トークンそのものは書かない。
    **`$CODEX_HOME` は書き込み可能なボリュームにする**(compose の `chiezo-codex-home`)——
    コンテナと一緒に捨てると、作り直すたびに登録時のトークンへ戻って同じことが起きる
  - **順番待ちは chiezo 側で持つ**(`media._slot` / `_others_running`)。ブリッジ側でも
    直列化されるが、**そこで待つと待ち時間がこちらの HTTP の時間切れに算入される**。
    **見るのは生成の表だけでは足りない** —— 同じ CLI は**会話でも掴まれる**。
    収集の層は無人で回っていて 1 回が数分かかるので、その最中に絵を頼むと
    「空いている」と読んで投げてしまい、ブリッジ側で並んで、待ったぶんごと落ちる
    (絵がちょうど 10 分で落ち続けたのがこれ)。会話は別の記録(`ai_inflight`)なので
    そちらも覗く。**自分のために走っている会話は数えない** ——
    文章の生成は中で会話の口を呼ぶので、待つと自分待ちになる
  - **認証情報がホーム配下で回る CLI は、CLI の起動を 1 本ずつにする**
    (`cli_slot`。`ROTATING_CREDENTIAL` = codex / antigravity)。2 本が同時に期限切れに
    当たると同じ refresh token で更新をかけ、後から届いたほうが上と同じ失効を踏む。
    **環境変数で受け取る claude は回らない**ので素通りさせる(並行に投げられる)。
    枠の確認のような短い問い合わせは `LOCK_WAIT` で待ちを切って 503 を返す ——
    長い会話の後ろに並ぶと、画面が数分固まったまま何も言わないことになる
  - **何が選べるかは、立ち上がってすぐ裏で聞いておく**(`lifespan` が `_probe_cli` を
    投げる)。聞かれてから聞きに行くと、最初に画面を開いた人が CLI の起動ぶん
    (実測で数秒)待つ —— しかも待った末に返るのは同じ答えなので、待たせる意味が無い。
    **裏へ回すのは、CLI が居ない・サインイン前のときに立ち上がりごと止めないため**。
    取れなければコードの控えに落ち、次に聞かれたときにまた試す。
    **codex は聞き取りを待たずに控えのファイルを読み足す**(`_fill_from_codex_catalog`)
    —— 聞き取りは CLI が空いているときしか走らないので、立ち上がった直後に会話が来ると
    一覧が空のまま残り、畳んだ名前(`gpt-5.6-sol-medium`)を解けずにモデル名として
    渡して 400 になった。ファイルを読むだけなので CLI は起こさない。
    **解くときはモデルごとの段でも照らす**(`split_model` / `_efforts_per_model`)——
    `efforts_now` はどのモデルでも通る段だけなので、上位だけが受ける `max` を解けなかった。
    **待つのをやめたら相手も終わらせる**(`_run_text`)—— 置き去りにすると、
    見ている者のいない CLI が 1 本残る
  - **モデルの一覧の取り方は CLI ごとに違う。** `agy models` は一覧を出すコマンドを
    持つ唯一の相手で、claude は `models` サブコマンドが無く(`error: unknown command
    'models'`)コードの控えを使う。**codex はコマンドの代わりにファイルを読む**
    (`_codex_catalog`。`$CODEX_HOME/models_cache.json` に、codex 自身がサーバーから
    取った一覧が落ちている)—— **CLI を起こさずに読める**ので枠も食わず待ち時間も無い。
    拾うのは `visibility` が `list` のものだけ(残りは内部用で、選ばせても意味が無い)で、
    並びは `priority` の昇順(先頭が既定のモデル)。
    **考える量も同じファイルから読むが、モデルごとに違う**(最上位だけが `max` を
    受ける、など)。ブリッジは相手ごとに 1 本の一覧しか名乗れないので、
    **どのモデルでも通る段階だけ**に絞る(`_catalog_efforts`)—— union にすると、
    モデルを選び直した拍子に通らない組み合わせができる。
    **codex に考える量のフラグは無く、設定キーで渡す**
    (`-c model_reasoning_effort=<段階>`。渡ったことは起動時の見出し
    `reasoning effort: <段階>` で確かめられる)。
    **あの控えは codex がセッションを立ち上げたときにしか書かれない** ——
    作り直したコンテナでは「codex だけモデルが選べない」ことになる
    (1 回使えば出る、では順序が逆)。`doctor` も `login status` も `app-server` も
    取りに行かない(どれも実測)。**存在しないモデル名で 1 回起こして取り直させる**
    (`_warm_codex_catalog`)—— 控えを取る段は立ち上げにあるので先に済み、そのあとの
    呼び出しは相手が 400 で弾くので**生成は走らない**(実測で 2 秒)。
    実在する名前を書くと、そこで 1 往復ぶん枠を使う。
    **起こすのはプロセスにつき 1 回だけ**(取れなかったときに聞かれるたび起こすと、
    画面を開くだけで何本も立ち上がる)。**認証情報を置けないときは起こさない**
    (起こしても取れない。印も立てないので、登録したあとに聞かれればそこで取りに行く)
  - **CLI の版は固定する**(`bridge/Dockerfile` の `CLAUDE_VERSION` / `CODEX_VERSION`。
    `npm install -g …@<版>`)。範囲で入れると焼いた日で中身が変わり、道具を絞るのに頼っている
    権限まわりのフラグの扱いが黙って動く。入った版が違えばビルドを落とす。
    **Dependabot は npm install の版を追わない**ので人が上げる。**agy は版を指定できない**
    (インストーラが常に最新を入れる)ので、下限(`AGY_MIN_VERSION`)で「キャッシュに当たって
    古いまま出来上がる」ことだけを防ぐ。以前は claude / codex も下限だけを持っていて、
    片方にしか下限が無かった頃は `opus` の別名が 1 世代前のモデルに解決されていた(実測)。
    **node の版が CLI の版の天井になる。** npm は `engines` に合う中でいちばん新しい
    版を選ぶので、取り出しのステージが古いと黙って古い CLI が入る ——
    claude-code は 2.1.198 から `node >= 22` を要求していて、`node:20-slim` では
    2.1.197 で頭打ちになっていた(下限を付けて初めて分かった。それまでは
    キャッシュのせいに見えていた)。**実行ステージと同じ Debian のタグを選ぶ**
    —— `claude.exe` はそこでビルドされた glibc に動的リンクしている。
  - **応答には実際に走ったモデルを載せる**(`_only_model`)。こちらが送るのは別名
    (`opus` など)で、どの世代に解決されるかは CLI が決める —— 頼んだ名前を返して
    いると、古い CLI が 1 世代前を選んでいても頼んだ側からは分からない。
    **名乗りが 1 つのときだけ返す**(claude の `modelUsage`)。途中で切り替わった回は
    2 つ以上になり、そこから 1 つ選ぶと選び方次第で署名が変わる
  - **CLI を 1 つ足すときに触る場所は 4 つある。** `cli_bridge.py`(起動コマンド・
    モデルの控え)だけ直しても動かない —— `entrypoint.sh` の `case`(**足りないと
    「未対応の CHIEZO_BRIDGE_CLI」で起動すらしない**)、`AUTH_CHECK`(**無いと
    「接続を試す」が通らず、画面から有効にできない**)、Dockerfile(CLI の導入)。
    実際に Gemini CLI を足したとき `entrypoint.sh` が取り残されて起動しなくなったので、
    `tests/test_bridge.py` が対応表の欠けを見張っている(その CLI は提供終了で外したが、
    検査は残してある)
  - **`GET /usage` は CLI にサブスクの枠を聞く**(`USAGE_CLIS` = claude / codex / antigravity)。
    codex は `codex app-server` に JSON-RPC で `account/rateLimits/read` を 1 往復
    (**`codex exec` は使わない** —— あちらは会話を 1 回走らせるので枠を食う。
    枠組みは実測済み: 未サインインで
    `codex account authentication required to read rate limits` が返る = メソッドは実在する。
    **サインイン済みで返る中身はまだ見ていない**)、
    antigravity と claude は print モードのスラッシュコマンド
    (`agy -p /usage` / `claude -p "/usage"`)。
    **claude だけ「使った割合」で言う**(antigravity は「残り」)—— 取り違えると、
    使い切った枠が「まだ全部残っている」ように出る。
    **JSON の前に警告が混ざることがある**(実測:
    `Warning: no stdin data received in 3s`)。stderr を stdout に混ぜて読んでいるので、
    1 行吐かれるだけで `json.loads` が落ちる —— `_json_tail` が最初の `{` から読む。

    **走っている最中は最後に取れた値を返す**(`_LAST_USAGE`。`stale: true` を立てる)。
    枠を聞くにも CLI を 1 本起こすので、認証情報が回る相手では待ち枠が要り
    (`cli_slot`)、長い会話の後ろでは取れない。**断るより、古いと分かる形で値を返す** ——
