# 話せる相手・鍵・取り次ぎ(/v1/ai/*)

話せる相手の定義と鍵の置き場、知識ベースを介さない素の口(`/v1/ai/backends`・`/v1/ai/complete`)、走っている依頼、控え。

## 相手の定義と鍵

- `app/providers.py` — **話せる相手の定義(URL・表示名・モデル候補はここに決め打ち)**。
  相手ごとに URL は 1 つに決まるので設定にしない —— 書き間違いの余地を増やすだけ。
  **ユーザーが決めるのは on/off・API キー・モデルの 3 つだけ**で、それらは
  `app/settings_store.py`(`/data/state/settings.db`)に入る。
  **既定のモデルは「AI設定」の面の相手ごとの欄で決める**(`POST /admin/ai/model`)。
  **会話のたびに選べるのは会話だけ** —— 無人で回る層(収集・ワーカー)は画面の前に
  人が居ないので、巡回ごとに書いていない限りここの値で走る。**候補に無い値も受ける**
  —— 一覧は相手から取るもので、取れていないことと「その名前が無い」ことを
  区別できない(弾くと、一覧が取れないあいだは何も指定できなくなる)。
  **候補が空なら、セレクトではなくその旨を出す** —— セレクトだけ出すと、
  選べないのが Chiezo の都合に見える。例外は `CHIEZO_LLM_URL` で指す相手で、
  LAN の別マシンを指す用途があり URL を決め打ちにできない。
- `app/anthropic_api.py` — **Claude API(Messages API)を OpenAI 互換の口に見せる変換**。
  chiezo の会話の層はどの相手も `/chat/completions` と `/models` で話すので、
  **形の違う相手だけ HTTP の出入口(httpx のトランスポート)で変換する**
  (`answer._llm_client` が `Provider.api == API_ANTHROPIC` のときだけ挟む)。
  呼ぶ側は相手を知らずに済み、引き直し・止め方・使用量の控えも同じ道を通る。
  **Anthropic の OpenAI 互換の口は使わない**(試すためのもので、考える量も
  拒否されたときの切り替えも使えない)。公式の SDK(`anthropic`。httpx2 の上に載り、
  chiezo の httpx とは別物として同居する)で呼ぶ。要点:
  - **道具を呼んだ回は、Claude が返したブロックを `RAW_KEY` に添えて返す** ——
    agent は assistant の発言を丸ごと積み直すので、考えた中身(thinking)を署名ごと
    送り返せる。崩して文字と呼び出しだけにすると考えた中身が落ちる
  - **拒否されて別のモデルに回った境目(`fallback` ブロック)より前の、考えた中身と
    道具の呼び出しは送り返さない・実行しない**(断られた側のもの)
  - **`temperature` / `top_p` は送らない**(Claude Opus 5 以降は 400)
  - **考える量はモデルの名前に畳む**(`folds_effort`。`claude-opus-5-high`)——
    `/models` はモデルごとに API が名乗る段(`capabilities.effort`)だけを並べる
  - **拒否(`refusal`)で本文が無ければ 422 で失敗として返す**(空の答えを保存させない)
  - **SDK の引き直しは切る**(`max_retries=0`。混雑の引き直しは `_post_with_retry` が持つ)
- `app/settings_store.py` — 管理画面から入れた設定の置き場。**`CHIEZO_STATE_DIR` が
  機能フラグを兼ねる**。**依頼文の言語(`prompt_language`)もここ** ——
  絵・音・動画・声を頼むときのプロンプトを何語で書くかで、**相手ごとではなく
  サーバー全体の設定**(「相手をどう呼ぶか」ではなく「頼む人にどう書いてほしいか」)。
  **画面はその他の面の「Claude Code 連携設定」の下**(`ai_settings.prompt_language_html`)——
  生成される設定に載る 1 行なので、その設定のすぐ下で決める。
  **Chiezo 自身は依頼文を書かない**ので、効かせ先は生成される CLAUDE.md ブロックの
  1 行だけ —— 設定ファイルを配り直すまで読む側の手元は変わらない。
  **自由入力にしない**(`PROMPT_LANGUAGES`)—— そのまま配る文面になるので、
  綴りの揺れが読む側への曖昧な指示になる。**「指定しない」と「未設定」は別**
  (未設定は既定の日本語に落ちるので、消すだけでは指定しないを表せない)。「答える」層そのものの元栓(`answer_enabled`)もここに持つ ——
  **既定は有効だが、それで勝手に動き出すことは無い**(相手が全部既定 off なので)。
  元栓は「相手を 1 つずつ切って回らずに機能ごと止める」ためのもの。`/data/corpus`(読み取り専用)にも `/data/notes`(「覚える」層の中身)にも
  混ぜない。**API キーは平文**(認証なし・LAN 内前提のサービスで暗号化しても守れるものが
  増えない)だが、**画面には二度と出さない**。
- `app/views/ai_settings.py` — 管理画面の「AI の相手」節と、on/off・API キーの受け口。
  **on にできる条件を画面側でも守る**: 鍵の要る相手は鍵が要る / 同居のコンテナ
  (推論サーバ・CLI ブリッジ)は**立っていなければ on にできない**(到達確認は並行に
  行う。直列だと立っていない相手の数だけ画面が遅れる)。`app/answer.py` 側でも弾く。
  **CLI の認証情報も管理画面から入れる** —— 登録のたびに相手ごとの写しを
  `state/bridge/<相手>/credential` へ書き出し(`settings_store.export_bridge_credential`。
  起動時にも DB から揃え直す)、ブリッジはそのディレクトリだけを読み取り専用で
  マウントして要求のたびに読む(再起動は要らない)。chiezo-app に「トークンを返す口」を
  開けずに済むのが要点。**設定 DB そのものはブリッジに渡さない** —— 全部の相手の鍵が平文で
  入っていて、ブリッジの中で動くのは道具を持ったエージェントなので、頼み方ひとつで読まれうる。
  写しは 0640(ディレクトリ 0750)で、ブリッジは compose の `group_add` で app の GID を足して
  読む。**settings.db は今も WAL にしない**(古い compose のまま `/state` を丸ごと
  マウントしているブリッジが読めるように)—— WAL の読み手は -shm への
  書き込みを要求し、read-only のマウントでは `unable to open database file` になる。
  **journal_mode はファイルに焼き付く属性**なので `PRAGMA` を書かないだけでは既存の
  ファイルが戻らない。接続のたびに `DELETE` を明示している(本番で 502 の原因になった)。
  **「接続を試す」が一度でも通るまで on にできない**(`provider_settings.verified_at`)。
  登録の有無でも到達確認でもなく「いま話せるか」を条件にする —— 認証情報が間違っていても
  到達はするし、会話して初めて失敗すると原因を追いにくい(本番で 502 になった)。
  確かめ方は `/models` を引くだけで、会話は 1 往復もしない(サブスクの枠を食わないため)。
  ブリッジだけは `/health?check=1` で CLI に直接聞く(`claude auth status` 等)。
  **認証情報を入れ替えたら印を消す**(まだ確かめていないため)。**管理画面は描画のときに
  相手へ問い合わせない** —— 記録された結果だけを見るので、落ちている相手があっても遅くならない。
  **認証の失敗(401)が返ったら、Chiezo がその相手を自分で止める**
  (`answer._stop_on_auth_failure` → `settings_store.disable_for_failure`)。401 は人が
  登録し直すまで直らないのに、on のままだとワーカーが空いた相手としてそこへ振り続け、
  頼むたびに同じ失敗を積んだ(本番で codex が落ち続けた)。**ブリッジは相手の 401 を 502 に
  包む**ので、状態コードではなく理由の文を読む(`is_auth_failure`)。止めるときは確認済みの印も
  消し、理由と日時を `disabled_reason` / `disabled_at` に残す。**状況の面の先頭と、トップの
  状況の札、AI設定の面のその行に知らせを出す** —— ワーカーは止まった相手を黙って飛ばす
  (`workers._switched_off`)ので、出さないと止まったことに誰も気づかない。
  **人が on に戻したら知らせを消す**(`set_enabled`)。ワーカーが飛ばすのは
  「止めた」と記録のある相手だけで、一度も設定していない相手は除かない
  (除くと設定の置き場が無い構成でワーカーが 1 つも振れなくなる)。

## いま走っている依頼

- **状況の面の「いま走っている AI への依頼」には、その回で終わったぶんも並べる**
  (`_round_done` / `usage_store.calls_by`)。**1 回の取り込みで何本も走る** ——
  巡回は区画ごとに AI を呼ぶので、出ていたのは**いま飛んでいる 1 本だけ**だった。
  終わったぶんは控えへ移るので、**「この回で何本目か」「さっきのは通ったのか」が
  状況の面からは読めない**(待たされているときに見に来る画面なのに、AI設定の面まで
  開いて時刻で突き合わせることになる)。
  **回の始まりは取り込みの開始時刻** —— 依頼元が同じでも、前の回のぶんまで
  引っ張ると括りの意味が変わる。**走っているものが先**(いちばん知りたい
  「いま何が詰まっているか」を下へ流さない)。**終わったぶんは「かかった時間」**
  (経過だと、終わっているのに時計が進み続けているように見える)。
  **収集を焼いている回だけ**(ダンプのソースには回という括りが無い)。
  **落ちたぶんは出ない** —— 失敗の控え(`app/ai_log.py`)が依頼元を持つように
  なったのは後からで、回への結び付けはまだしていない

## モデル名の控え

- **モデル名の控え(`app/providers.py` の `models`)は古くなる。** 相手からモデルが
  消えると 404 になり、画面には「llm error 404」としか出ない。**選んでも保存してもいない
  ときは、相手に聞いて先頭へ差し替える**(`answer.ensure_model`)。404 のときは
  「モデル名が違うかもしれない」というヒントも返す

## 入口の断りと控え

- **Chiezo が動かしている CLI から、AI を使う口への依頼は入口で断る**
  (`_asks_an_ai` の中間層 + `media.refuse_bridge_caller`。ブリッジのコンテナの
  住所を引いて突き合わせる)。**相手を指名して頼んでいるのに、指名された側が
  別の相手へ聞きに行く**のは依頼として成立していない —— 誰が答えたのかも、
  誰の枠を使ったのかも読めなくなる。塞ぐのは絵・音・動画・声・文章の生成だけでなく、
  `/v1/ask`・`/v1/chat`・`/v1/ai/complete`・`/v1/talk`・収集の下書きと即時実行も。
  **口ごとに書かずに中間層で見る** —— 口ごとだと付け忘れが「枠が二重に減って
  初めて気づく」漏れになり、しかも本体の検査より後ろなので、壊れた本体では
  素通りして 422 になっていた。
  **道具を取り上げるだけでは止まらない** —— ブリッジ越しの相手はシェルを持って
  いるので、MCP から生成の道具を外しても `curl` や Python で REST の口を直接
  叩ける(実際に叩かれた: 依頼元が `Python-urllib/3.11` の生成が、こちらの
  依頼文を英訳した内容で立った)。**塞ぐなら経路ではなく入口**。
  読む口(search / doc / filter)は通す —— ブリッジの値打ちはそちらなので
- **AI に渡したものと返ってきたものを控える**(`app/ai_transcript.py`。
  `state/ai_transcripts.db` + `state/ai-transcripts/<日付>/<id>.txt`)。
  **`app/ai_log.py` の「中身は残さない」は変えない** —— あちらは失敗の観測で、
  こちらは**シェルを渡している相手が何をしたか**を読むための別の控え
  (agy には `--dangerously-skip-permissions` を渡している。シェルを外す前は、頼んでいない
  生成を curl で立てられた)。
  残すのは依頼文・**相手の生の出力(CLI の stdout/stderr)**・応答の 3 つで、
  途中経過がいちばん効く。**一覧は先頭 `HEAD_MAX` 字だけ、全文はファイル**
  (DB に何十 KB も積むと一覧を引くたびに運ぶ)。**先頭しか出していない塊には
  そう書く** —— 印が無いと、読み手は目の前のものを全部だと思って判断する。
  行とファイルは同じ日数で捨て、`CHIEZO_AI_TRANSCRIPT_DAYS=0` で丸ごと止まる。
  **途中経過はブリッジが返したときだけ入る**(`chiezo_trace`)。会話の口が
  捨てていた頃は、絵の回以外いつも空だった —— 包んでいるのはシェルを持った
  エージェントで、道具を何回引いたのかも本文には出ない

## /v1/ai/backends・/v1/ai/complete

- `/v1/ai/backends`(GET) / `/v1/ai/complete`(POST) — **知識ベースを介さない素の口**。
  `/v1/chat` は必ず抽出を混ぜるので、**自分のプロンプトと材料を持っているアプリ**には使えない
  (無関係な抜粋が載り、トークンも余分に使う)。借りたいのは「話せる相手と鍵」だけ、という
  使い方のために分けてある(例: 別のアプリのサマリー生成)。`backends` は管理画面で
  on にした相手を、モデル(相手に聞けた場合はその答え)・エフォート・モデル指定の要否・
  **web 検索を持つか**(`web`)つきで返す。
  `complete` は渡された `messages` をそのまま 1 往復投げる(履歴の組み立ては無い)。
  `knowledge=true` なら、API の相手にも知識を読む道具(`agent.KNOWLEDGE_TOOLS`)を貸して往復を回す
  (`agent.complete_with_tools`。抽出は混ぜず、引くかは相手が決める)。CLI ブリッジの相手は
  MCP で繋がっているので何もしない —— API の相手だけが Chiezo の知識を引けない、という差を埋めるため。
  `sources`(ソース名のパターン。先頭 `!` は除く)で引いてよい範囲を絞れる。API の相手は道具の側でも
  断り(`agent.source_allowed`)、CLI ブリッジの相手には system に範囲を足して伝えるだけになる
  **`system` ロールを許す**のはこの口だけ —— プロンプトを組むのは呼ぶ側だから。
  **呼ぶ側は `requested_by` で名乗れる**(控えに `api:<名乗り>` として残り、
  画面の「依頼元」に開いて出る)。**必須にはしない** —— 名乗りが無いだけで
  AI を借りられなくなるのは、この口の値打ち(鍵だけ借りる)に合わない。
  ただし**無名の依頼は後から追えない**ので、**配る CLAUDE.md ブロックでは
  必須として書く**(`app/claude_config.py`)—— AI に叩かせる経路はこちらが
  文面を握っているので、そこで名乗らせるほうが確実
  **`stream=true` で本文を書かれた端から SSE で流す**(`main._complete_events`。`meta` → `delta`… → `done`、
  失敗は `error` のあと `done`)。書き終えるまでの時間は本文の長さでほぼ決まる(Claude API の速い相手でも
  入力 5,000 字・出力 2 字は 1.5 秒、出力 250 字は 5〜11 秒)ので、声で話すアプリが 1 文目から使い始められるように。
  中身は `answer.stream_message`(`/v1/ask` の流し込みと同じ `_stream`)。**依頼元は流す生成器の中で巻く**
  (ハンドラが返ったあとに往復が走るので、外で巻いても控えに名乗りが付かない)。
  **道具を貸して往復を回すとき(API の相手への `knowledge` / `web`)は 400** —— 途中の発言は答えではない

## 止める・走っている依頼・web

- **走っている 1 往復は、人が止められる**(`ai_inflight.ask_to_stop` /
  `stop_wanted`・`POST /v1/ai/inflight/{id}/stop`・画面の「止める」)。
  **1 回の上限を伸ばしたぶん、ここが歯止めになる** —— 打ち切っても枠は返らない
  (本番で、5 区画のうち 4 区画ぶんが返ったあとの 1 本が 840 秒で切れ、集めたぶんも
  枠も消えた)ので「走っているなら待つ」に倒し、既定を 60 分まで伸ばした。
  そのままでは暴走した 1 本が取り込みを 1 時間占めるので、時間ではなく人が
  止める形にする。**止めるのは押した人のワーカーではない**(`--workers 2`)——
  控えに印を書くだけで、**往復を掴んでいるワーカーが数秒おきに見に来て自分で降りる**
  (`answer._watching_for_stop`。`STOP_POLL_SECONDS`)。手を離せば繋ぎが切れ、
  **ブリッジはそれに気づいて CLI を殺す**(`bridge/cli_bridge.py` の `_spawn` が
  `CancelledError` で `kill`)—— ここまで効かないと、答えを読む者のいない CLI が
  枠を食い続ける。**二度押しは咎めない**(表は数秒古いので普通に起きる)。
  状態は「止めています」と出す —— 押してすぐ行が消えるとは限らないので、
  黙っていると「押したのに何も起きない」に見える
- `/v1/ai/inflight`(GET) — **いま走っている依頼**(`calls` = 相手との往復、
  `jobs` = 絵と音と動画と読み上げ)。控えの表に行が立つのは**往復が終わってから**なので、
  走っている最中は何も見えなかった —— 頼んだ本人が待っているうちは分かるが、無人で
  回る層が動かしているぶんは、遅いのか止まっているのか呼べてすらいないのかの区別が
  付かない(CLI ブリッジ越しの相手は数分かかる)。始まりに 1 行立て、**終わったら
  `finally` で消す**(成功でも失敗でも時間切れでも)。**この表にだけ依頼文そのものを
  残す**(`prompt`。`PROMPT_MAX` で切る)—— 失敗の控え(`ai_log`)が中身を持たないのは
  500 件を溜め続けるからで、こちらは終われば行ごと消える。そして
  **止めるかどうかは中身を見ないと決められない**(同じ相手へ似た大きさの依頼を
  2 本投げていると、相手・モデル・大きさだけではどちらか分からない)。
  **モデルの欄には実際に走ったものを出す。** 選ばなかったときに送るのは
  `answer.PLACEHOLDER_MODEL`(= `chiezo`)というただの印で、
  **モデル名ではなく「そちらで決めて」の合図** —— そのまま控えると、
  そういう名前のモデルが走ったように読める。実物は**走った後にしか分からない**ので、
  応答が名乗る `model` を `answer.model_of()` で採り、`cfg.ran_model` に置く
  (`cfg.model` は書き換えない —— agent は同じ `cfg` を使い回すので、書き換えると
  次のターンで選んでもいないモデルを名指しで送ることになる)。走る前に立てる
  `calls` の行には**印を書かず空にする**(相手の名前だけが残るほうが、嘘の名前が
  並ぶよりよい)。
  **文章の生成は `calls` と `jobs` の両方に出る** —— 中で会話の口を呼ぶため。
  同じものだと分かるよう `calls` 側が抱えている job の id を `job_id` に持ち
  (`ai_inflight.on_behalf_of`。**引数で引き回さず ContextVar で渡す** ——
  会話しか使わない経路までジョブの都合を持たせないため)、
  **画面と数はそこで 1 本に畳む**(`views/ai_history.running_rows`)。
  畳まないと 1 本の依頼が 2 件に見え、枠の残りを読み違える。

  **誰が頼んだかも持つ**(`caller`。`ai_inflight.called_by()` を**入口で 1 回だけ巻く**)。
  無人で回る層(収集の時計)が動かしているぶんと、外のアプリが頼んだぶんを
  見分けるため —— 待たされているときに見に来た人がまず知りたいのは
  「これは自分が頼んだものか」で、相手とモデルだけでは分からない。
  印は `collect:<名前>` / `api:<名乗り>` / `admin` / `media`(生成は名乗りがあればそれ)で、画面には
  `caller_label()` が開いて出す(素の id では読めない)。**`<種別>:<名乗り>` は
  どの種別でも開く** —— 外のアプリは名乗れるので、`api` とだけ出したのでは
  どのアプリが枠を食っているのか読めない。**名乗りは受け口で均す**
  (`caller_of`。改行を畳み `CALLER_NAME_MAX` で切る)—— 外から来る値なので、
  そのまま画面の欄に入れない。**分からないときは空欄**
  (「不明」と書くより読み違えない)。**済んだぶんにも同じ値を残す**
  (`usage_store` の `caller` 列)ので、終わった後も見分けが付く。

  **巻けるのは、答えが関数の中で出る経路だけ。** SSE で流す `/v1/ask` と
  `/v1/chat` は本体が生成器の中で動くので、関数を抜けた時点で印が外れる ——
  そこは空欄になる。**区別が要るのは「無人か、人か」**なので、
  収集(`collect:`)と外のアプリ(`api`)が付いていれば用は足りる。
  置き場は `state/ai_inflight.db`
  (`app/ai_inflight.py`)。**期限は始めた側が行に書く** —— 待つ秒数は相手で桁が違う
  (ブリッジ 3,660 秒 / 直叩き 120 秒)ので、掃除する側が 1 つの数字で切ると、粘っている
  相手を消すか止まったものを何十分も残すかのどちらかになる。
  **落ちた行は脈で気づく**(`ping` / `beat_at`)—— 待っている側が「止めてくれ」を
  見に来るついでに打つので、**面倒を見ているワーカーが消えれば数十秒で行も消える**。
  期限だけに頼っていた頃は、**1 回の上限を 60 分へ伸ばしたぶん落ちた行が 1 時間
  居座り**、しかも「止める」を押しても手を離す相手がもう居なかった
  (押しても何も起きない)。**止めてくれと言われたまま残っている行も掃除する**
  (`STOP_GRACE_SECONDS`)—— 生きているワーカーなら数秒で消すので、
  残っているなら待っている相手はもう居ない。**脈を打たない経路もある**
  (流し読みの会話)ので、期限の側も残す。**プロセスの中の変数に
  持たない**(`--workers 2` なので、画面を出したワーカーと走らせているワーカーが
  別だと何も見えない)。ワーカーごと落ちて `end()` を通らなかった行は期限で消える
- **`complete` の `web=true` で相手自身の web 検索を開ける**(既定は開けない)。
  ニュースの収集のように「いまの外の情報」が要る仕事を、`/v1/chat` の抽出を混ぜずに
  頼めるようにするため(例: 市況ニュースの収集・銘柄調査)。
  **持っているのは CLI ブリッジで包んだ相手だけ**(`Provider.bridge`)——
  API で直に叩く相手は OpenAI 互換の口に検索の項目が無い。
  **頼まれて開けないときは 400 で断る。** 黙って道具無しで答えさせると、呼ぶ側は
  それを「調べた結果」として受け取り、学習データから作った話が最新の材料として
  保存されてしまう(実際に「取得不可」と答えるべき場面で古い首相の名前が返った)。
  応答の `web` に**実際に開けたか**を載せるので、呼ぶ側は取り違えを検出できる

## 管理画面の相手の表

- 管理画面は**頼めることの一覧 + 相手ごとに 1 行の表**にまとめてある
  (`app/views/ai_settings.py`)。**行の欄はその相手で何ができるかしか示さない**ので、
  そもそも何を頼めるのか(と、まだ頼めないもの)は上の一覧が受け持つ。
  話す相手と絵・音の相手を別の節に分けていた頃は、**同じ相手(鍵も on/off も共通)が
  2 か所に出ていて、どちらが効くのか読めなかった**。「できること」の欄が
  話す・絵・音を同じ書き方(`✓` / `⚠ 理由`)で並べる。
  **印に絵文字を使わない** —— 環境によっては豆腐になり、いちばん見たい列が読めなくなる。
  **無効な相手は行ごと薄くする**(`tr.off`)。ボタンの文字だけでは、行が増えるほど
  いまどちらか読み取りにくい。**「接続を試す」の戻り先には節の印を付ける**
  (`#ai-providers`)—— 付けないとページの先頭へ戻され、結果が画面外のままになる。
  自前の GPU(ComfyUI)と ElevenLabs は「話す相手」ではないので、鍵・on/off・
  「接続を試す」もこの表の自分の行に置く(`owns_toggle`)。**ElevenLabs は
  会話ができないのではなく、会話の口が「先にエージェントを作って `agent_id` で話す」形で
  `app/providers.py` の枠(OpenAI 互換に 1 往復)に入らない**、が正確なところ。
  「接続を試す」は繋がるかに加えて**チェックポイントの有無まで見る**
  (立っていてもモデルが無ければ 1 枚も描けない)。**絵と音は別のファイルが要る**ので
  どちらが何件あるかも返す
