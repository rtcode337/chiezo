# 生成(絵・音・動画・声・文章)と見比べ

`app/media.py` ほかの生成の層、見比べと採用の印、頼めることの一覧(`/v1/capabilities`)。

## 生成物の見比べ

- **生成物の見比べ**(`media.job_groups()` / `job_group()` / `pick_job()` /
  `/v1/media/groups` / 画面の `/admin/media` と `/admin/media/{組の名前}`)—
  **何案か作らせた絵と音を、依頼文つきで並べて選ぶ**ところ。**音は AI 自身が聴けない**ので、
  聴き比べる場所がここしか無い。決めごとは 3 つ:
  - **一覧と中身で口を分ける**(`job_groups()` / `job_group(key)`)。一覧が運ぶのは
    見出し・依頼日時・種類・件数まで —— 全部の案を積んで返すと、開くつもりのない
    依頼の絵と音まで毎回運ぶ(音は 1 本で数 MB)。**名前の無い依頼の見出しは
    依頼文の 1 行目**(「(名前なし)」が並ぶと一覧からどれを開くか決められない)
  - **束ねる名前は頼む側が付ける**(`group`)。生成の時刻や相手で機械的に括ると、
    別々のつもりの依頼が同じ組に混ざる。**名前の無い依頼も 1 件 1 組として出す** ——
    消すと「作られなかった」と読める
  - **選んだ結果は記録に残し、頼んだ AI が引きに来る**(`media_picks` /
    `GET /v1/media/picks`)。会話で番号を伝える形にすると、選ぶ人と頼んだ AI が
    別のやり取りにいるときに拾えない
  - **元にしたものも依頼文と並べて出す**(`source_url` / `source_mode`)。
    渡した中身(bytes)は相手へ送ったら消えるので、**指し先だけを控える** ——
    `/media/...` か外の URL に揃え、読めない形(手元の絶対パス)は控えない。
    **依頼文だけでは出来上がりを読めないことがある**のが理由で、参考にしたものの
    欠点をそのまま引き継いだ生成物を前に、「指示が悪いのか、参考が悪いのか」を
    切り分けられなかった。**絵に限らない**(曲の参考音源も読み上げも同じ扱い)。
    `edit` / `reference` のまま出さず「これを直した」「これを参考にした」と言葉にする
    —— どちらかで結果の読み方が変わる
  - **見る口と頼む口を分ける**。この層が持つのは読むのと印を付けるところまでで、
    頼む口は `app/views/media_ask.py` が別に持つ(作る話と見る話を混ぜない)

## 外部の相手のエラー

- **外部の相手のエラーは本文を 600 字まで返す**(`media_backends.remote_error`)。
  300 字では 429 の `Quota exceeded for metric: … limit: 0` がちょうど切れて、
  「枠を使い切った」のか「そもそも枠が無い」のか分からなかった(2 度踏んだ)。
  **鍵はヘッダで送っている**ので本文には載らない。429 には「時間をおいても直らないなら
  無料枠に含まれていない可能性」というヒントを添える

## 見比べの画面

- `app/views/media_compare.py` — **AIへの依頼の面(`/admin/media`)**。並びは見比べ →
  「AIと会話する」(`admin.answer_status_html`。AI設定の面から移した —— 頼む話はこの面に
  まとめ、鍵を預ける面とは分ける)→ 作ってもらう。何案か作らせたものを
  依頼文つきで並べて選ぶところ。もとはやること層の画面だったが、あちらはタスクの
  入れ物で、**見比べているのは生成物** —— 相手・鍵・使用量・依頼の履歴と
  同じ「AI に頼んだこと」の面にある。決めごとは 3 つ:
  - **生成の口は置かない**。あるのは読むのと印を付けるところまでで、
    頼む口は `app/views/media_ask.py` が別に持つ(作る話と見る話を混ぜない)
  - **JS を持たない**(管理画面の流儀)。絵は `<img>`、音と動画はブラウザ内蔵のプレイヤー、
    文章は `<pre>` を `<details>` に畳む。印を付けるのもフォームの POST + 303
  - **組の URL は percent-encode してから HTML のエスケープを通す**(`group_url`)。
    組の名前は人が付けるので `#` や `&` や `/` がそのまま入りうる ——
    素で埋めると別の組を指すか、URL が途中で切れる(`quote` は HTML のエスケープではない)
  `/` からの転送先はトップのまま(どの面を先に見たいかは人によるので名指ししない)

## 生成の REST と頼めることの一覧

- `/v1/media/backends?kind=`(GET) / `/v1/media/image`・`/audio`・`/video`・`/speech`
  ・`/transcribe`(POST) / `/v1/media/jobs/{id}`(GET) / `/media/{path}`(GET)
  — **絵・音・動画・声を作る口**
  (MCP の `image_*` / `audio_*` / `video_*` / `speech_*` / `transcribe` と同じ実体)。
  知識を引くのとは別の仕事だが、**MCP の登録先を増やさない**ために同じサーバーに載せている。
  実体は `app/media.py`(ジョブと置き場)/ `app/media_backends.py`(相手ごとの作り方)
  / `app/media_providers.py`(相手の定義。ComfyUI / Codex / Antigravity / Gemini / OpenAI / ElevenLabs)。
  **kind が違っても層を分けない** —— ジョブ・置き場・掃除・中断の後始末・配信は同じ仕事で、
  違うのは頼むときの語彙(サイズ / 種類と長さ / 尺 / 声)だけ。分けると同じ後始末を
  kind の数だけ持つことになる。呼び分けは `media_backends.generate_for` の 1 か所。
  `MediaProvider.kinds` がその相手に頼めるものを持ち、一覧は kind で絞る
  (Lyria に効果音は頼めないし、自前の GPU に読み上げは頼めない)。要点:
  **待たない**(job を返し `image_status` / `audio_status` で引く。生成は数秒〜数分で、
  待つと呼び出し側が先に切れる)。**中身そのものは返さない**(1 つ 1〜2MB あり、道具の結果はまるごと
  コンテキストに載る。返すのはパスと URL)。**ジョブは SQLite に持つ** ——
  chiezo-app は `--workers 2` なので、プロセス内の辞書だと頼んだワーカーと聞かれた
  ワーカーが別のときに「そんなジョブは無い」になる。設定 DB とは別ファイル
  (あちらは CLI ブリッジが読み取り専用でマウントしている)。**中断は Exception では
  拾えない** —— MCP の接続が切れるとタスクごと畳まれ、`except Exception` を素通りして
  job が running のまま残る(実際に起きた)。`CancelledError` を捕まえて記録し、
  ワーカーごと落ちた場合に備えて読み出し時に古い running を畳む(`_reap_stale`)。
  **走っている間は印を打つ**(`_heartbeat` / `_touch`。`HEARTBEAT_SEC` ごとに
  `updated_at` だけを更新する。順番待ちの間も打つ —— 待ち枠は `_run` の内側)。
  **これが無いと、止まったことに気づくのが生成の制限時間ぶん遅れる** ——
  chiezo が再起動されると走っていた生成はそこで消えるが、job は running のまま残り、
  引きに来た側は「まだ作っている」と読んで待ち続ける(実際に落ちた 2 本が running の
  まま残り、気づいたのは 14 分後だった)。かつて猶予を「生成の上限 + 60 秒」に
  していた頃は、**縮めれば作っている最中のものを殺し、伸ばせば止まったものを何十分も
  残す**の板挟みで、しかも kind ごとに別の数字が要った。印があれば「相手が遅い」と
  「面倒を見る側が消えた」を区別できるので、猶予は `HEARTBEAT_SEC` の数回ぶんで足りる。
  **保存する拡張子は中身に合わせる**(Gemini の絵は JPEG のみ、音は mp3 / wav / flac)。
  **配信はパスを解いてから**
  (`../` を踏ませない)。**配るときは `nosniff` と `Content-Security-Policy: sandbox` を付ける**
  (`main.MEDIA_HEADERS`)—— 置き場には持ち込みも外部の生成結果も入り、Chiezo と同じオリジンから
  配るので、文書として開かれても動かない形にする。**持ち込みの拡張子は一覧から選ぶ**
  (`media.upload_suffix`。名前の拡張子をそのまま使わず、一覧に無ければ種類ごとの既定に
  付け替える。SVG は断る)。**持ち込みも文字起こしの multipart も `UPLOAD_MAX_BYTES` を
  読みながら数えて 413**(`media.read_upload`。申告の大きさで先に断る中間層もある)。
  **URL で渡された元(文字起こし・絵の元)は `app/outbound.py` を通す** —— 名前を引いて
  手元・LAN のアドレスを断り、転送も 1 段ずつ確かめ、上限で読むのを止める。Chiezo 自身の
  `/media/…` を URL で渡されたときは取りに行かずに置き場から読む(`media._own_media`)。**置き場が無ければ MCP の道具ごと出さない**(使えない道具を
  コンテナに並べない、notes と同じ扱い)。**外部の相手の鍵は「話す相手」のものを流用する**
  (`credential_from`)—— 同じ鍵を 2 か所に入れさせると、片方だけ古くなる。
  そのために `app/providers.py` に `openai` を足してある(OpenAI 互換なので話す相手にも
  そのまま使える)。**例外は「話す相手」に対応が無い相手だけ**(ElevenLabs は会話が
  できないので借り先が無く、鍵も on/off も自分で持つ = `owns_toggle`。ComfyUI と同じ扱い)。
  **on/off も「話す相手」と共通** —— そちらで無効にした相手には
  絵も音も作らせない(`media_backends.unusable_reason`)。鍵を持っている相手を止めたのに
  片方だけ動き続けるのは、止めたつもりの人にとって事故になる。**元栓(「答える」層)を
  止めたら全部止まり、MCP の道具も出さない**(`media.tools_enabled`)。
  出し分けは **401 = 鍵が無い(入れれば直る)/ 403 = 無効(画面で有効にする)**。
  **サイズの語彙はこちらが `幅x高さ` で統一**し、相手の語彙(Gemini は比率、OpenAI は
  決まった組み合わせ)への変換は各バックエンドが受け持つ。**画素をそのまま使う相手
  (`exact_sizes` = ComfyUI)は一覧以外のサイズを断る**(`media.create_job`)——
  学習解像度を外れると絵は崩壊するのに、生成は成功として返るため、受け取った側は
  絵を見るまで気づけない。GPU を回す前に断るのが親切。
  **頼んだ側の名乗り(`requested_by`)を job の列に持つ** —— 同じ表に外のアプリ・
  無人で回る層・手元から持ち込んだぶんが並ぶので、相手とモデルだけでは
  「これは自分が頼んだものか」も「誰が枠を食ったのか」も読めない
  (見に覚えのない依頼が 1 件出てきたとき、出どころを当てる手がかりが無かった)。
  話す口(`/v1/ai/complete`)と同じく**必須にはしない**が、
  **名乗らなかったぶんは User-Agent へ落とす**(`media.caller_name`)——
  自己申告だけに頼ると、いちばん出どころを知りたい依頼が空欄のまま残る。
  MCP は 1 往復ごとに独立している(`stateless_http=True`)ので `initialize` の
  clientInfo はツールを呼ぶ時点には残っておらず、毎回必ず届くのは HTTP のヘッダのほう
- **画面からも頼める**(`app/views/media_ask.py`。見比べの中の「作ってもらう」)。
  **会話できない相手(ComfyUI・ElevenLabs)に頼む道はここだけ** —— あちらは
  話せる相手ではないので、会話の道具に混ぜても届かない。
  **「画面に課金の走る操作を置かない」は認証なしで外に開いていた頃の決めごと**で、
  管理画面には当てはまらない(もともと Chiezo を操作している人だけが開ける前提で、
  会話も収集の即時実行も押せば枠を使う)。
  `/admin/media/{key:path}` は総取りなので、**頼む口を先に登録する**こと
- **姿勢の見本を絵で渡せる**(`pose`)。`edit`(これを直す)/`reference`(絵柄を合わせる)
  とは役割が別で、**この姿勢で描かせる**ための口。**言葉で姿勢は伝わらない** ——
  相手もコマ数も参考の渡し方も変えて 13 回頼み、13 回とも同じ足が前に出た
  (腕だけ振れて脚は構えたまま)。棒人間を渡した 1 回で通った。自前の GPU では ControlNet に、
  CLI ブリッジ越しの相手には**参考の 1 枚目**として渡る(向こうは ControlNet を
  持たないので、依頼文で「1 枚目は姿勢」と指す)
- **自前の GPU も絵を受け取れる**(`edits=True`)。`/upload/image` へ置いてから、
  グラフで img2img(`edit` / `reference`)と ControlNet(`pose`)に繋ぐ。
  **グラフは 1 本のまま継ぎ足す** —— 3 通り持つと、サンプラーの設定や保存先が
  3 か所に散って、片方だけ直したときに気づけない。`denoise` は役割で変える
  (`edit` は元を保ちたいので低く、`reference` は構図まで引きずられると別のものが
  描けないので高く)。ControlNet は**正負の両方に掛ける** —— 片側だけだと、
  姿勢を外した絵に罰が掛からず効きが半分になる
- **Leonardo.Ai も選べる**(`leonardo`)。**web アプリの契約とは別建て**で、
  公式の言い方が "API access is separate from free or web app subscriptions" /
  "usage is billed in dollars"。読み違えると、契約したのに 401 が返り続ける。
  **既定には絶対にしない**(`PREFERENCE` の最後)—— ドル建ての従量課金なので、
  既定で選ばれると頼むたびに黙って請求が伸びる。モデルは相手に聞く
  (`platformModels`)。投げた時点では絵を持たない相手なので、出来るまで引き直す
- **参考(`reference`)は複数渡せる。** 役割が分かれることがあるため ——
  姿勢の見本と絵柄の見本を同時に渡す、など。**役割の名前は持たない** ——
  渡した順に相手側のファイル名(`source.png` / `source-2.png` …)が決まるので、
  「1 枚目は姿勢」と依頼文で書けばよい。種類を増やすより後から効く。
  **直すほう(`edit`)は 1 枚だけ**(何枚も同時に直す指示が成立しない)。
  ブリッジには `images` で送り、`image` にも 1 枚目を入れる —— 頼む側だけ先に
  焼き直したとき、古いブリッジでも少なくとも 1 枚は届く
- **絵は `edit` で「一部だけ直す」ことができる**(`media.start_image_job` の `source`)。
  **一から描き直させると、直したい 1 か所以外も毎回描き変わる** —— 同じ文面で頼んでも
  絵柄・ポーズ・大きさが振れるので、通っていたところまで作り直しになる
  (コマ 6 枚のスプライトで 1 コマ直すたび、残り 5 コマの光沢と体格が変わった)。
  受け取るのは**置き場のパスか URL** だけ(文字起こしと同じ規則。手元の絶対パスは
  見えない)。**渡すのは絵そのもの** —— ブリッジは別のコンテナなので、こちらのパスを
  渡しても開けない。**直せる相手は `MediaProvider.edits`** で、いまは CLI ブリッジ越しの
  2 つだけ(エージェントなので作業ディレクトリに置いた絵を開ける)。**出来ない相手には
  頼む前に 400 で断る** —— 黙って一から描くと、直したつもりの絵が全部描き変わって返り、
  受け取った側は見比べるまで気づけない。ブリッジ側は**文面を「編集の指示」に切り替え**、
  「直す箇所以外は変えるな」と言い切る(「描いて」と言うと、置いてある絵を参考にした
  別の絵を描く)。**置いた元の絵は成果として拾わない**(今書いたので mtime も新しく、
  除かないと「直っていない絵」を返す)
- **曲は `reference` で参考の音を渡せる**(`media.start_audio_job` の `source`)。
  **参照はファイルではなく id で指す**ので、compose の前に `POST /v1/music/upload` で
  登録する 1 往復が要る(`_elevenlabs_upload`)。**素の prompt には参照を置く場所が無い**
  ので、1 区間だけの composition plan にして `conditioning_ref` を付ける(参照は先頭
  30 秒まで)。**効果音の口は文字しか受け取らない**ので、渡されたら断る —— 黙って
  無視すると、出てきた音を「参考にした結果」として受け取り、似ていない理由が
  分からないままプロンプトを書き直すことになる。**印は絵と分けて持つ**
  (`audio_reference` / `edits`)—— 1 つにまとめると、絵を直せない相手に絵を渡しても
  素通りする。**既存の楽曲を参考音源にしない**(規約で禁じられていて、画面からは
  止まるのに API では素通りする。`AUDIO-CREDITS.md` と同じ判断)
- **音は `sound`(効果音 / 曲)と `seconds` で頼む**(`media.start_audio_job`)。
  同じ「音」でもモデルが別物で、相手によっては口そのものが分かれている
  (ElevenLabs は `/sound-generation` と `/music`。絵と動画はさらに別で `/flows/*`)。ComfyUI も系統でグラフが変わり、
  **Stable Audio Open は text encoder(T5)を別に読む**が ACE-Step は all-in-one。
  **どちらの系統かは名前で見分ける**(`is_audio_checkpoint` / `_is_ace`)——
  ComfyUI に「このチェックポイントは何用か」を聞く口が無く、GPU に載せてから
  間違いに気づくのは高い。**長さは黙って丸めない**(`_check_audio` が上限超えを 400 で断る)
  —— 短くして返すと、呼んだ側は頼んだ尺で出来たと思ったまま短い素材を受け取る。
  **尺を渡す口が無い相手(Lyria)に秒数を渡されたら断る**(無視すると同じ勘違いが起きる)。
  **歌詞が空なら器楽として頼む** —— ゲームの BGM に歌が乗ると台詞と喧嘩する
- **動画は「待ち時間」「尺」「重さ」の 3 つが絵と違う**(`media.start_video_job`)。
  **上限を別に持つ**(`CHIEZO_VIDEO_TIMEOUT`、既定 1200 秒)。
  **job を畳む猶予は kind で分けない** —— 走っている側が印を打つので、
  見ているのは「生成に何秒かかるか」ではなく「面倒を見ている者がいるか」。
  **尺は丸めない**(`_check_video`)。相手ごとに受け付ける値が飛び飛びで
  (Sora は 4/8/12、Veo は 4/6/8)、寄せると「6 秒で頼んだのに 8 秒が返る」になる ——
  数分と数十 MB を使ってから気づく。**一度に頼めるのは 2 本まで**(絵は 4 枚)。
  **相手はどこも非同期**(頼んだ時点では id しか返らない)なので、待ち方は
  `media_backends._await_remote` に 1 つだけ置く —— 覗きに行く間隔は相手が決めている
  (ElevenLabs は動画で 10 秒に 1 回まで)。**Gemini だけ口が 2 通り**で、
  Omni Flash は絵と同じ `interactions`、Veo は `:predictLongRunning` を待って
  **鍵つきで**取りに行く(署名済み URL ではない)。名前で見分ける(`_is_veo`)
- **声は向きが逆の 2 つ**(`media.start_speech_job` / `media.transcribe`)。
  **文字起こしだけ job にしない** —— 返るのが文字(数 KB)なので置き場も掃除も配信も
  要らず、その場で返すほうが呼ぶ側の手数が少ない。そのぶん口の形も違う(multipart)。
  **自前の GPU には読み上げを頼めない**(ComfyUI 本体に TTS のノードが無く、外部の拡張
  しか無い —— 入れたものでノード名も引数も変わるので、こちらからグラフを組み立てられない)。
  **声は名前で頼める**(`_elevenlabs_voice_id` が id に直す。id を控えている人はいない)。
  一覧に無い名前は**そのまま id として渡す** —— こちらが一覧を取り損ねただけ、という
  場合に頼みごと自体を潰さない。**生の PCM には WAV の殻をかぶせる**(`_ensure_wav`)——
  Gemini は 24kHz の生 PCM を返すことがあり、そのまま保存すると拡張子も中身も
  再生できないファイルになる(受け取った側は開くまで気づけない)。
  **文字起こしに渡せるのは置き場の中か届く URL だけ** —— chiezo はコンテナの中で
  動いていて、頼んだ人のディスクは見えない(受け取れるように見せると、あるはずの
  ファイルが「見つからない」と返ってくる)
- `/v1/capabilities`(GET) — **chiezo 経由で AI に頼めることの一覧**
  (会話・読み上げ・文字起こし・画像・動画・音楽・SE)。
  語彙は `app/capabilities.py` の 1 か所に持ち、
  **画面も REST も同じものを見る** —— 会話は `app/providers.py`、絵と音は
  `app/media_providers.py` と持ち主が分かれているので、分類まで散らすと
  「何が頼めるのか」を数える場所が無くなる。
  **分類は仕事の単位で切る(実装の単位ではない)** —— 音楽と SE は job の `kind` としては
  どちらも `audio` だが、モデルも相手も別物(Lyria は曲しか作れない)なので別に数える。
  **読み上げと文字起こしを分けてあるのも同じ理由**(仕事の向きが逆で相手も別物。
  まとめると「読み上げはできるが文字起こしはできない」相手を「声が使える」と言うことになる)。
  `supported=false`(**実装が無い**)と「相手がいない」(実装はあるが鍵が未登録・GPU が無い)
  は別扱いにする。次にすることが違うため。**いまは全部 true だが仕組みは残す** ——
  次に分類が増えたときにまた要るし、消すと 2 つがまた同じ言葉に潰れる

## 「いま頼めるか」

- **「いま頼めるか」を数えるのは `capabilities.usable_now()` 1 か所**
  (`/v1/capabilities` とブロック生成が同じものを見る)。分けると、
  画面に出る相手と設定ファイルに書かれる相手がずれる
